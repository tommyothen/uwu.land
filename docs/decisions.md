# uwu.land — decisions

Why the architecture is the way it is. Git history records what changed; this
records which alternative was rejected and on what grounds, so a future change
back to one of them starts from the original reasoning rather than from scratch.

| Date | Decision | Notes |
| --- | --- | --- |
| 2026-07-10 | Restructure as a turborepo | Use pnpm workspaces, Turborepo, Biome, and TypeScript-source internal packages. |
| 2026-07-10 | Use Hono for the API Worker | Keep routing small and explicit for Cloudflare Workers. |
| 2026-07-10 | Use `@cloudflare/vitest-pool-workers` | Exercise KV and Worker behavior inside workerd-backed tests. |
| 2026-07-10 | Keep KV as the redirect hot path | D1 becomes the metadata plane; redirects stay KV-only. |
| 2026-07-10 | Anon-lane URL dedup + normalization; anon creates recorded in D1; maintainer ban/abuse CLI scripts | Normalized-URL KV reverse index dedupes anonymous creates only; D1 rows power abuse reporting; blocking stays KV `banned:<domain>` managed via pnpm scripts. |
| 2026-07-10 | Verify Clerk JWTs in-worker | Use `@clerk/backend` JWT verification with configured issuer and JWKS, without Clerk network calls in tests. |
| 2026-07-10 | Landing redesign: "Riso Post Office" visual system | Riso grain + postal metaphor on the 2021 brand; Bricolage/Instrument/Space Mono; one GSAP submit choreography; shadcn tokens. |
| 2026-07-10 | apps/web on React Router v7 + @cloudflare/vite-plugin (replacing Next/OpenNext) | app used no Next-specific features; drop the adapter layer and its operational risk (build fork-bomb class bugs, env split-brain). |
| 2026-07-13 | Billing: Clerk Billing → direct Stripe Billing (Checkout + Billing Portal + webhooks) | PayPal + 3DS support; Clerk checkout renders neither. Clerk remains auth-only. |
| 2026-07-23 | Lifetime First-Class + 25% launch offer | $4/mo, $79 lifetime; launch: $3/mo (forever coupon), $59 lifetime (launch price); yearly removed from sale, grandfathered for entitlement. |
| 2026-07-25 | Reprice lifetime: $79/$59 → $40/$30 | $79 was ~20 months of monthly; $40 is 10 and the launch $30 is 7.5, which undercuts a year of subscribing on purpose. With no users yet, adoption is worth more than revenue per sale, and marginal cost per user on Workers/KV/D1 is negligible. Both launch prices are now exactly 25% off, so the advertised discount is literal. Nothing had been sold, so no grandfathering. |
| 2026-07-25 | Ship the `azp` and CORS dev-origin controls as opt-in vars | `CLERK_AUTHORIZED_PARTIES` and `CORS_DEV_ORIGIN` are absent from `wrangler.jsonc` and inert when unset. An `azp` allowlist that rejects every token is a worse outage than the cross-app risk it prevents, and Clerk omits `azp` outside browser-minted tokens; leaving the dev origin in the production allowlist is the thing actually worth fixing, and an absent var cannot ship it by accident. |
| 2026-07-25 | No per-minute create limit | Kept the single daily fixed window and left burst limiting as a future pricing lever. Reviewed the related abuse-surface tradeoffs at the same time and accepted them deliberately; the detail lives in the local operations runbook rather than here. |
| 2026-11-19 | Key IP-based controls on the IPv6 /64, abuse block included | One residential /64 rotated through addresses to dodge the anon quota, stats limit and abuse block, so `ipKey` collapses IPv6 to its /64 and IPv4-mapped IPv6 to the bare IPv4. Rejected a separate /48 for the abuse block: ISPs that delegate /56s pack 256 households into one /48, so a strike from one would block hundreds of unrelated anonymous users for a day. A spammer holding a /56 still gets 256 buckets; the destination rejections below cut what each bucket is worth. Abuse blocks written before this change sit under the old full-address key and are deliberately not read any more: they expire within 24 hours anyway, and a legacy lookup would add a Durable Object call to every anonymous create for that one day. |
| 2026-11-19 | Reject IP-literal, dotless and over-deep hosts for every caller; walk at most five labels for bans | IP literals and single-label hosts have no parent domain for the ban walk and reach local or private services. Nothing documented relies on them, so authenticated callers lose them too rather than splitting the rules. Hosts past ten labels are rejected and the ban walk reads at most the last five labels, bounding KV reads per create; a ban deeper than five labels no longer matches. |
| 2026-11-19 | Anonymous creates cannot target well-known URL shorteners | An anonymous link to bit.ly and friends launders a banned target past the ban list. A static set in `shorteners.ts` rather than KV: the list barely changes and needs no tooling. Signed-in callers keep them, since their abuse is handled per account. |
| 2026-11-19 | Bans sweep existing links; no ban check at redirect time | `pnpm ban`, `purge:domain` and the daily feed sync mark matching links `pending_delete`, and the reconciler cron removes their KV entries, so a ban takes links down (100 every five minutes) without a second delete path. Each mark matches the URL the sweep read as well as the slug, so a slug freed and reused mid-sweep is spared. Re-checking `banned:` on every redirect was rejected: it adds a KV read per label of the destination host to the hot path to cover only the minutes before the reconciler runs. The reconciler does re-check before publishing a `pending_publish` row, since a create that passed its ban check just before a ban and sweep would otherwise go live; that costs the same up to four KV reads again per publish, off the redirect path. Bare public suffixes are refused for bans and sweeps using `tldts` with private suffixes included (`co.ke`, `github.io`, `pages.dev`), since a sweep makes a suffix ban take down every link under it. A hand-written list was rejected after it missed `co.ke`. |
| 2026-11-19 | Reserve site, account and apps/web paths as slugs | `uwu.land/login`, `/billing`, `/support` and friends were claimable by any free account and pointable at a phishing page. `RESERVED` in `slugs.ts` stays a plain set matched case-insensitively and now covers API routes, every apps/web route, and the common site and account paths. It gates creation only; any existing link on a newly reserved slug keeps redirecting and is dealt with by hand if abusive. |
| 2026-11-19 | Tombstone every deleted slug permanently | Old QR codes and printed links keep sending traffic after a delete, so a slug is never reissued, not even to its original owner (no ownership column to keep in sync, no "who deleted it" edge cases). `slug_tombstones` is written by an `AFTER DELETE` trigger on `links`, so every path that removes a row (user deletes, ban sweeps, purge scripts, the reconciler's banned-before-publish branch, and an older Worker still running between migration 0010 and the deploy) leaves a tombstone without remembering to write one; until the row is removed it holds the slug itself. This replaced an explicit write in the delete handler, which missed the sweep and purge paths. Slugs deleted before 0010 left no record and cannot be recovered. All deleted slugs are tombstoned, not just custom ones, because a deleted random slug is just as claimable as a custom slug. Create checks the table for custom and authenticated random slugs; a `BEFORE INSERT` trigger on `links` backs up every other path (the anonymous generator only checks KV) and raises a unique-violation message so the existing retry and 409 handling apply unchanged. Rows are never purged; at one short row per delete the table stays trivially small. |
| 2026-11-19 | Refetch Clerk's JWKS at most once a minute per isolate | An unknown `kid` used to refetch on every request, so junk tokens turned into one Clerk call each and a Clerk rate limit could then fail real sign-ins after a key rotation. A genuinely new kid seen within a minute of the last fetch is rejected until the minute passes; Clerk publishes keys before signing with them, so that window is rarely hit. |
| 2026-11-19 | Create the Enforcement DO schema on writes only | Reads (`isBlocked`, `fixedWindowUsage`) and `link:<slug>` reconciliation no longer create tables, so they leave no storage behind. Objects created before this change keep their empty tables; they are tiny and not worth a sweep. |
| 2026-11-19 | Prune webhook replay records after 30 days | The daily cron deletes `stripe_webhook_events` and `clerk_webhook_events` rows older than 30 days. Signatures expire after 5 minutes, Stripe retries for 3 days and Svix for about one, so 30 days is ample. Stripe rows still referenced by a subscription or lifetime purchase are kept for their foreign keys. `deleted_users` stays permanent. |
| 2026-11-19 | Reconcile pending links fewest-attempts first | The cron batch orders by `reconcile_attempts` then `last_reconcile_at`, so rows that keep failing cannot fill the batch and starve healthy publishes. From a row's 12th failed attempt onwards, every failure also logs `link_reconciliation_stuck`. |
| 2026-11-19 | Anonymous dedupe keys on the fragment | Stripping it folded `/app#/a` and `/app#/b` into one link, so the second caller got a slug that redirected to the first fragment. Redirects carry the fragment and single-page apps route on it, so it is part of the destination. Dedupe hits also echo the stored URL, since rows hashed under the old key can hold a fragment the caller did not send. |
